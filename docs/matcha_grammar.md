# Matcha / Matcha-D の文法（公開されている用例から読み取ったもの）

Matcha の公式 BNF は公開されていない。以下は Elecode「Matchaとは」と、花房孟胤「法律には形式言語がない」第4・5回の用例から読み取った文法で、mext の構文チェッカ（`matcha-check`、`python3 -m mext.matcha_check`）はこれに従って実装している。

## 1. 字句

- 全角の `＃％＾＠＆｜＄？！＋：＜＞＝～〜` は半角と同じに扱う。全角の括弧 `（）` は法文中で普通に使われるので、記号としては扱わない。
- 空行は無視する。`//` から行末まではコメント。行頭の `::` は見出しコメント。
  - `//` と `::` は、花房「法律には形式言語がない」第4回の例（`::（１）について`、`// 略`）に出てくる。Elecode「Matchaとは」の記号の説明にはないので、`//` を行コメントとして扱うのは、その用例からの読み取りである。
- **要素の先頭**の位置でだけ記号として働く文字: `#` `%` `?` `「` `"` `(` `+` `!`（`"` は Matcha-D。§5）。要素の先頭とは、行頭と、`(` `:` `<=` `=>` `~>` `&` `|` `!>` の直後を指す。それ以外の位置では本文の文字として扱う。
- どこでも演算子になるもの: `<=` `>>` `~>` `=>` `!>` `&` `|` `@` `^` `:`。
- `as ラベル` は、ラベル（空白を含まない語）の直後が行末か演算子のときだけキーワードになる。
- `not` と `!` は `>>` の直後のときだけ結論の否定になる（Matcha-D。`>> not X` と `>> !X` は同じ意味）。

## 2. 構文（EBNF）

```ebnf
document    = { line_item } ;
line_item   = section | priority | element ;
section     = "::" text NEWLINE [ INDENT list(elem) DEDENT ] ;
priority    = "::" "優先" "$" label ">" "$" label ;               (* Matcha-D *)

element     = [ mark ] ( claim | requirement | issue | ref | group | plain ) , postfix ;
mark        = "+" | "!" ;                                         (* 成立 / 不成立 *)
claim       = "#" [ text ] [ "^" text ] ;                         (* #主張^根拠 *)
requirement = ( "「" text "」" [ text ] | '"' text '"' [ text ] | "%" text ) [ "^" text ] ;
                                                                  (* 「要件」でない^但書 も可。"要件" は Matcha-D *)
issue       = "?" text ;                                          (* 論点 *)
ref         = "$" label ;
group       = "(" list(ctx) ")" [ "@" text ] ;
plain       = text ;                                              (* 規範・言い換えを素の文で書いた場合 *)

postfix     = { "<=" operand(fact)                                (* あてはめる事実 *)
              | ":"  operand(elem)                                (* 言い換え・下位要件／論点のあてはめ *)
              | "~>" operand(fact)                                (* 理由（論点のみ） *)
              | "=>" operand(elem)                                (* 規範（論点のみ） *)
              | ">>" [ "not" | "!" ] text                               (* 結論 *)
              | "as" label
              | "!>" "$" label { "&" "$" label }                  (* Matcha-D: 例外 *)
              } ;

operand(c)  = inline(c) | NEWLINE INDENT list(c) DEDENT ;
inline(fact)= fact { ( "&" | "|" ) fact } ;
fact        = ( text [ "as" label ] | group | element ) [ "@" text ] ;   (* 事実@評価 *)
list(c)     = item(c) { sep item(c) } ;
sep         = "&" | "|" | NEWLINE ;                               (* 改行は AND の省略 *)
```

## 3. レイアウトの規則（インデントと継続行）

Matcha は括弧 `( )` でも字下げでもブロックを書ける。チェッカは次のように解釈する。

1. **ブロック**: 行末の `:` `<=` `=>` `~>` の次の行がより深く字下げされていれば、そこから同じ深さの行の並びが被演算子になる。字下げされていない場合は次の 1 行だけを被演算子とし、警告を出す（カント例の `? 天才とは =>` など）。
2. **継続行**: 行頭が `<=` `@` `:` `~>` `=>` `!>` `as` の行は、前の行の続きとみなす。それを受け取れる最も内側の要素につながる（`「要件」: %定義` の次の行の `<= 事実` は `%定義` につながる）。
3. **結論 `>>`**: 行頭の `>>` は、同じ深さで始まった行の先頭の要素の結論になる。同じ深さの要素がなければ、それより浅い最も近い要素の結論になる。行の途中の `>>` は、その行の先頭の要素の結論になる。
4. **区切り**: `&` と `|` を同じ並びに混ぜるとエラーになる（括弧でまとめる）。`|` と改行（AND の省略）が混ざると警告になる。
5. 行末の `&` の次の行が浅い字下げの要素なら、その `&` は外側の並びの区切りとみなす（カント例）。

## 4. 意味の検査

- ラベル: 重複、未定義の `$参照`、未定義の `!>` の対象、自分自身への `!>`、`:: 優先` の対象をそれぞれ検査する。
- 成否の印の整合性: AND の下位要件に `!` があるのに親が `+`、などを警告する。印のない論点は、その規範の印を引き継ぐ。
- 論点 `?` に規範も結論もない場合は警告する。
- 文言中の `AND`/`OR`/`NOT` は警告する（Matcha の演算子は `&` と `|`）。
- `<=` の後（事実の位置）の「…」と `"…"` は、要素の先頭なので要件と読まれる。これを警告する（事実の文が発言などの引用で始まるなら、『』や “…”（曲がった引用符）に替える）。
- 事実に付いた `as` のラベルが英小文字だけの単語なら警告する（英文の行末の「… as drivers」がラベルと読まれた可能性がある）。
- 相互例外（`$a !> $b` と `$b !> $a`）は情報として表示する（複数の Extension がありうる）。

## 5. Matcha-D（例外の拡張）

**原典にあるものと、Matcha-D で足したもの**: 名前付けの `as 名前` と参照の `$名前` は原典にある（第4回の例: `=> %規範 as 第三者の規範` と、別の事件での `$第三者の規範 <= 事実`）。Matcha-D は、次の表のうち `!>`、`>> not`・`>> !`、`:: 優先` を足し、`as` を主張にも付けられるようにした（原典の用例では `as` は規範に付いている）。


| 記法 | 意味 | デフォルト論理での読み |
|---|---|---|
| `>> 結論 as d` | 主張 d に名前を付ける（原典の `as` を主張に使う） | デフォルト d |
| `X !> $d` | X は d の例外 | X の前提が成り立てば d の正当化が阻却される（X は d に優先） |
| `>> not 結論` / `>> !結論` | 結論の否定（同じ意味） | 古典否定 ¬結論 |
| `:: 優先 $d2 > $d1`（`:: priority $d2 > $d1` とも書ける） | 優先順位だけを宣言する | d2 ≻ d1（Brewka 型の優先度付き Extension） |
| `"要件"` | 「要件」の別表記（英文のため。0.5.0 以降） | 「要件」と同じ（文言は `"要件"` のまま原子になる） |

- **要素の前の `!` と結論の否定の違い**: `!#主張` は「この主張は成立しない（証明されない）」という著者の判定で、メタレベルの話である。`>> not X` は「X が偽である」ことの主張である。前者は「立証に失敗した」、後者は「反対事実が立証された」にあたる。`>> !X` の `!` は位置（`>>` の直後）で区別されるので、構文上は衝突しない。
- **`"要件"`**: 英文では「」を打ちにくく、また読み手に見慣れないので、法文上の文言の要件を `"public use"` のように ASCII の二重引用符でも書けるようにした。要素の先頭に置いたときだけ要件の記法になり、それ以外の位置の `"` は本文の文字である（`the sign said "closed"` は事実の文のまま）。入れ子はなく、次の `"` で閉じる。閉じた後の語は、「」と同じく接尾の文言になる（空白で区切って原子の文言にする）。`「X」` と `"X"` は別の文言なので、同じ要件を両方で書いたなら `[ai] same` でまとめる。日本語の文書では、これまでどおり「」を使う。
- `!>` のない対立（ニクソン・ダイアモンド）は優先順位を与えない。そのため複数の Extension になる。
