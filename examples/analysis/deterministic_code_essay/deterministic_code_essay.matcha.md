## 1. 文書の論証の要約

**主な結論**（第4段落）: AI を使うシステムでは、規則として書き下せる判断はすべて AI に書かせたコードで行い、書き下せない判断だけを AI に直接させるべきである。

**筋**:

1. AI は同じ質問にも違う答えを返すことがあり、業務の判断ではこの揺れが問題になる（第1段落）。だから判断を AI に直接させない。
2. 判断の手続きを AI に決定論的なコードとして書かせるべきである。理由は三つあり、揺れがない、人が読めて後から検証できる、誤りが再発しない、である（第1・第2段落）。
3. ただし、文章の意味を読み取る判断や事実を評価する判断は規則として書き下せないので、AI に任せるしかない。その場合は理由とともに記録し、コードの部分と分ける（第3段落）。
4. 以上から主な結論が出る（第4段落）。

**範囲**: 文書は短く（4段落）、主な結論も一つなので、全文を書き起こした。

## 3. 書き起こしの判断

- **評価（`@`）としたもの**: 「AだからB」の「から」にあたる五つの判断。
  - L30 決定論的であること → 揺れがなくなる
  - L32 人が読める → 後から検証できる
  - L34 コードの誤りは再発しない、AI の誤りは再発しうる → コードのほうが誤りの再発を防げる
  - L41 意味の読み取り・事実の評価という例 → 規則として書き下せない
  - L43 書き下せない → AI のほかに任せる先がない
- **例外（`!>`）**: `AI直接 !> $回避_書けない`。第1段落の「判断を AI に直接させるのではなく」という原則を、第3段落の「AI に任せるしかない」が書き下せない判断について覆す、と読んだ。原文の「ただし」が例外を示している。`:: 優先` にしなかったのは、原文が「両方成り立つがこちらが勝つ」と比べているのではなく、「ただし」で原則の適用を外しているからである。
- **主張の分割**: 原文の「判断を AI に直接させない」は全称の規範である。第3・第4段落で判断が「書き下せる／書き下せない」に分けられるので、それぞれの対象ごとに主張を立てた（L15・L19）。「書き下せる判断」のほうは例外がなく、そのまま結論の「書き下せない判断**だけ**」の根拠になる。
- **対象による範囲の限定**: 最初の版では `コード判断` に要件 `%規則として書き下せる` を入れていた。しかし、あてはめる事実が自分の対象の言い換えにしかならず、形の点検（§6）でこの主張がどの Extension にも出なかった。そこでこの要件を外し、範囲の限定は対象（`<= 規則として書き下せる判断`）で表すことにした。
- **成否の印**: 原文は要件の成否を個別に判定していない（すべて肯定的に述べている）ので、`+` / `!` は付けていない。

### 見つけた論証の穴（書き起こしでは直していない）

1. **「AI に任せるしかない」（L43）**: 人が判断するという選択肢が検討されていない。第3段落は「書き下せない → AI に任せる」と直結しているが、その間にある「AI のほかに担い手がない」は示されていない。
2. **記録と分離（L48–50）の根拠がない**: なぜ記録と分離で足りる（「よい」）のかが書かれていない。第2段落の理由二（検証できること）を援用しているようにも読めるが、原文はそれを明示していない。根拠 `^` を空のままにした。また、記録と分離をしても、第1段落の問題（揺れ）は残る。この点に原文は答えていない。
3. **理由三の事実の強さ（L34）**: 「コードの誤りは一度直せば二度と起きない」は事実として書かれているが、実際には評価を含む強い主張である（直し方の誤り、仕様の変化、同じ種類の別の誤りがありうる）。原文のとおり事実として写した。
4. **AI が書いたコードが正しいかという前提**: 原文は、AI に書かせたコードが意図どおりの手続きになっていることを暗に仮定している。理由二（人が読める）が部分的にこれに答えているが、論証の中でははっきり結びついていない。穴として残した（補っていない）。
5. **書き下せるかどうかを誰がどう決めるか**: 結論は「書き下せる／書き下せない」の区別に依存するが、その線引きの基準は第3段落の二つの例だけである。
