# matcha-analysis（matcha分析）

文書の論証を Matcha / Matcha-D に書き起こす。書き起こしは解釈であり、あなた（AI）の仕事である。だから、**どの行が原文のどこから来たか、何を補い、何を落としたか**を、人が追える形で残す。

## 準備

- `python3 -m mext.matcha_check --help` が動くかを確かめる。動かなければ `pip install git+https://github.com/JRF-2018/mext`。
  - pip が externally-managed で入らなければ、`python3 -m venv` で venv を作って入れるか、clone したディレクトリを `PYTHONPATH` に加える。
  - 文書の URL を WebFetch で取れない（http と https の転送が繰り返されるなど）ときは、`curl -L` で取る。
- 書く前に読む:
  - `references/writing_matcha.md`: 文書を書き起こすときの考え方と型、よくある誤り
  - `../matcha-default-extensions/references/matcha_grammar.md`: 文法
- メモを書くときに読む: `references/memo_and_revision.md`（メモの章立て、形の点検、書き直しの規律）
- 手元にこれらがない場合は、https://github.com/JRF-2018/mext の `skills/` を読む。
- 引数は文書のファイル `X.md`（貼られた文章なら `X.source.md` として保存）。出力は同じディレクトリに `X.matcha`・`X.matcha.md`。原文は書き換えない。
- 会話への返答もファイルも、**利用者の言語で**書く（最初の一文から）。
- 利用者の言語が英語なら、mext のコマンドに `--lang en` を付けるか `MEXT_LANG=en` にする（道具の出力も英語になる）。

## 手順

1. **範囲を決める**: 主な結論と筋をつかむ。主な結論が 4 つ以上か 1 万字を超えるなら、聞けるなら範囲を聞く（聞けなければ「主な結論すべて」）。論証を含まない文書なら、そう書いて終える。詩・物語・描写・願いや呼びかけが中心で、理由から結論を導く筋がわずかしかない文書では、その性格を先に利用者に伝え、聞けるなら、軽い書き起こし（主な筋だけ。試算は作らない）でよいか、通常どおりにするかを聞く（聞けなければ軽い書き起こしにし、そう書く）。
2. **書く**: `writing_matcha.md` の型で `X.matcha` を書く。
   - 先頭に `// 原文: X.md` と `// matcha分析: AI（モデル名）による書き起こし。Matcha-D は非公式の拡張。`
   - 各主張・事実・評価の直前に `// 出典: 第N段落「短い引用」`、補った前提には `// 補った前提: 理由`。
   - 各主張に `as ラベル`。前の主張の結論を要件にするときは `$ラベル`。
   - 道具に読ませる判断（結び方、事実の種別、補った前提）はコメントではなくメモに書く。
3. **構文チェック**: `python3 -m mext.matcha_check --tree X.matcha`。エラーをなくし、`--tree` で構造が意図どおりかを見る。
4. **事前の予測**: **最初に解く前に**、メモ `X.matcha.md` を作り、「事前の予測」の節に、主な結論ごとの見込みを書く。後から書き換えない。
5. **形の点検と磨き上げ**:

   ```bash
   python3 -m mext init --solve X.matcha -o X.check.mext
   python3 -m mext lint X.check.mext
   ```

   `memo_and_revision.md` に従って、主な結論が出るか、lint の警告を見る。書き直すなら `snapshot` → 修正 → `diff` で、**原文への忠実さと粒度のためだけに**直す。
   この `X.check.mext` は書き起こしの形を点検するためのもので、ここで計算される Extension は分析の結果として報告しない（Extension の計算と審査は mext分析の仕事）。利用者が「書き起こしだけ」「Extension は計算しない」と頼んだ場合も、手順 5 と 7 は省かない。
6. **メモを書く**: `memo_and_revision.md` の章立てで `X.matcha.md` を仕上げる（対応表、結び方と事実の種別の表、補った前提、落としたもの、改訂の記録）。
7. **記録**: 最後に一度 `python3 -m mext solve X.check.mext` を実行し、この時点の `X.matcha` と `X.matcha.md` のハッシュ値を残す（後で人が直したかを見分けるため）。以後は解き直さない。

## 守ること

- **原文にない主張を作らない**。原文の論証が弱くても、強くして書き起こさない（弱さはそのまま写し、メモで指摘する）。
- 原文の文言を論証の都合で変えない（縮めるときも意味を変えない）。
- 立場を紹介・比較する文書で、原文が両立しないとする立場は、「…と説明する」のような報告ではなく、否定し合う結論として書く（`writing_matcha.md` §2.10）。
- 条文・判例は原文に引かれていれば `^根拠` に書く。なければ自分の知識で補わない（補うなら「補った前提」として明示する）。
