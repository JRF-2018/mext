# 書き起こしのメモと、磨き上げの規律

## メモ `X.matcha.md` の章立て

```
# matcha分析: X

## 1. 文書の論証の要約   … 主な結論と、それを支える筋。書き起こした範囲
## 2. 対応表            … 原文の箇所（段落・引用）→ X.matcha の行番号とラベル。言い換えた場合はその旨
## 3. 書き起こしの判断   … 何を評価（@）・例外（!>）・優先（:: 優先）としたか、その理由。次の二つの表を含める
                         （mext分析で .mext の [ai] に移す）:
                         - 結び方: 二つ以上を並べた箇所ごとに、行・AND/OR・明示か読みか
                           （手がかりがなければ「読み」でよい。根拠を作らない）
                         - 事実の種別: W に置いた事実ごとに、記述・仮定・確認済み・著者の主張のどれか
## 4. 補った前提        … 一覧と理由。前提の文言（評価・要件・事実の文言）をそのまま書く（[ai] の supplied に移す）。
                         後の審査で最も疑われるべきものであることを明記する
## 5. 落としたもの       … 書き起こさなかった部分と理由
## 6. 事前の予測        … 最初に解く前に書いた予測（書き換えない）。形の点検との食い違いの追記
## 7. 構文チェックと形の点検 … matcha_check と lint の結果、主な結論が Extension に出るか、見つけた論証の穴
## 8. 改訂の記録        … 版ごとに、何を受けて何を直したか、diff で見えた変化。改訂しなければ「なし」
## 9. 次の一歩          … mext分析に進むときの注意
```

## 形の点検で見ること

- 主な結論が、少なくとも一つの Extension（文書が支持する側なら preferred）に含まれるか。含まれなければ、**書き起こしの誤り**（ラベルの付け忘れ、`!>` の向き、文言の不統一など。直す）か、**原文の論証の穴**（直さずにメモに書く）かを判断する。
- lint の警告。とくに、同語反復の評価（判断の段階を書き分ける。原文が本当に一段で飛んでいるなら原文の飛躍としてメモに書く）、一段の主張が多い、行き止まりの主張（原文がつないでいるなら `$ラベル`・`!>`・`:: 優先` でつなぐ）。

## 書き直すときの規律

- 書き直す前に `python3 -m mext snapshot X.check.mext` で版を保存し、書き直した後に `python3 -m mext diff X.check.v1.mext X.check.mext` で比べる。
- 書き直してよいのは、**原文への忠実さと粒度を上げるため**だけである。**結論が出る・出ないを理由に書き直してはならない**。
- 何を受けて何を直したかを、メモの「改訂の記録」に書く。書き直しは目安として 3 回まで。残る警告は理由とともにメモに書く。
- `X.check*.mext` と古い版の `.matcha` は消さない（改訂の経緯を人が追えるように）。
