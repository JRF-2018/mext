# 読みを比べる

## 1. 対応づけ（`[match]`）

```
@mext-compare 1
a: A/killing.mext
b: B/article.mext

[match]
match "人を殺してはいけない〔本稿の議論〕" "One should not kill people" ; 同じ結論（B は英語の読み）
match "著者の解答に作業仮説の乱用がある点に留意が必要である" "著者の解答には作業仮説の乱用がありうると留意すべきである" ; 同じ留保。B は「ありうる」と弱めている
match "@社会便益を個人の義務へ接続する規範的選択" "@社会の協力の利益から各人の一般的な不殺義務を導いてよい" ; 同じ橋渡しの判断
```

- 文言は、結論の文言、〔対象〕を除いた文言、主張のラベル、`#主張名`、評価の `"@評価"`、`[atoms]` の文言のどれでもよい。ラベルや `#主張名` で指すと、その主張の結論どうしを比べる。`¬…` で否定を指せる。文言に `"` を含むなら `'…'` で囲む。
- **同じ命題**とは、原文の同じ箇所の同じ主張を、同じ向き（肯定か否定か）で指すものである。次の場合は、対応づけたうえで理由に書く: 主張の強さが違う（「…である」と「…かもしれない」）、対象の書き方が違う（〔本稿の議論〕と〔理想化された社会〕）、一方が立場の報告（「著者は…と考える」）で他方が立場そのもの。
- 次の場合は対応づけない: 原文の別の箇所の主張、一方の結論が他方の前提（中間の結論）にあたるもの（レポートの §2 に書く）、向きが逆のもの。
- 言語が違う読み（日本語と英語）も、原文の箇所で対応づける。
- 前提の対応は、**同じ判断**（同じ事実から同じ要件へのあてはめ、同じ橋渡し）を指すものだけにする。決め手の表に出たものから始めればよい。

## 2. 違いの分け方

`mext compare` の「違い」の列と §3（対応のない結論）を、原文に照らして次のどれかに分ける。

| 分類 | 例 | レポートでの扱い |
|---|---|---|
| 書き起こしの誤り | 原文にない主張、向きの誤り、出典の取り違え | どちらの読みの誤りかを、原文の引用で示す |
| 粒度の違い | 一方が判断を中間の要件に分けた、一方が一段にまとめた | 結論の成否が変わらなければ、決め手の違いとして書く。分けた側の決め手のほうが争点として具体的 |
| 判断の違い | 同じ評価の review（ok / doubtful）、補った前提の有無、結び方（AND / OR）、`!>` と `:: 優先` の有無 | 原文の手がかりを示し、どちらが原文に近いかを述べる。手がかりがなければ、判断が分かれうる箇所として書く |
| 原文の曖昧さ | 原文がどちらにも読める | **それ自体が所見**である。どちらの読みでも結論が同じかを書く |

とくに見るもの:

- **成否が違う**: 最も重要。どの前提・優先・結び方の違いから来るかを、両方の `mext explain` と `mext sensitivity` でたどる。
- **一方だけが補った前提に依存する**: 補った側の読みは、原文の論証を補強しているかもしれない。補わない読みでも成り立つかを確かめる。
- **共通の決め手**: 二つの読みが独立に同じ判断を決め手にしたなら、原文の論証の弱点（争点）である見込みが高い。ただし、二つの読みが同じ AI によるなら、独立とはいえない。
- **報告型と主張型**: 一方が立場を「…と説明する」の形（報告型）で書き、他方が立場そのものを結論にしている（主張型）と、Extension の数と成否が大きく違う。原文が立場を主張しているか、紹介しているかを確かめる。主張型の読みが、立場の中での説明（「前者では…と説明する」）まで立場の採用で条件づけていると、原文にない「他方の立場では成り立たない」が生じる（`../../matcha-analysis/references/writing_matcha.md` §2.10）。

## 3. レポートの章立て（`A.vs.B.compare.md`）

```
# 読みの比較: A と B

## 0. 結論      … 3〜6 行。二つの読みはどこで分かれ、主な結論の成否や依存がどう変わるか。
                  共通の決め手（原文の論証の弱点の候補）と、一方の読みだけの結果（書き起こしの選択の候補）を分けて書く
## 1. 二つの読み … 誰が（どの AI か人か）、いつ、mext の版、範囲、メモの要点。mext compare の §1（全体）の要約
## 2. 対応       … 対応づけた結論の数と、対応のない結論（理由: 書き落とし、中間の結論、別の命題）。[match] の判断のうち迷ったもの
## 3. 分かれ目   … 違いごとに: mext の出力、原文の該当箇所、§2 の分類、どちらが原文に近いか
## 4. 共通の決め手 … 両方の読みで決め手になる前提。原文の論証の争点として
## 5. 総評       … 比較して初めて見えたこと。比較の限界（読みの作り手が同じ AI か、範囲の違い、比べた AI 自身の偏り）
## 付録: ファイル一覧（A.vs.B.compare、A.vs.B.compare-result.md）
```

`mext compare` の出力は「（mext の出力）」と明記して、手を加えずに引くか、`A.vs.B.compare-result.md` を名前で参照する。
