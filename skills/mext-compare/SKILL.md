# mext-compare（読みの比較）

同じ文書の二つの読み A と B を比べる。比べることで、**一つの読みでは見えない、書き起こしの選択に依存した結果**を見つける。両方の読みで同じ前提が決め手なら、それは原文の論証そのものの弱点である見込みが高い。一方の読みでしか成り立たない結論や、一方だけが補った前提に依存する結論は、書き起こしの選択の結果である見込みが高い。

決定論的なのは `mext compare` の部分だけで、**どの結論・前提が対応するか（`[match]`）と、違いの解釈はあなた（AI）の判断である**。判断はすべて比較のファイル `A.vs.B.compare` に理由つきで残す。

## 準備

- `python3 -m mext --help` が動くかを確かめる。動かなければ `pip install git+https://github.com/JRF-2018/mext`。
- 読む: `references/comparing.md`（対応づけの考え方と、違いの分け方、レポートの章立て）。必要なら `../matcha-default-extensions/references/reading_results.md`（出力の読み方）。
- 手元にこれらがない場合は、https://github.com/JRF-2018/mext の `skills/` を読む。
- 引数は二つの `.mext`（解いたもの）。原文（`// 原文:` の行が指すファイル）と、それぞれのメモ（`X.matcha.md`）も読む。どちらの読みのファイルも書き換えない。
- 会話への返答もファイルも、**利用者の言語で**書く。英語なら mext のコマンドに `--lang en` を付ける。

## 手順

1. **確かめる**: 二つの `.mext` が同じ文書の読みかを、`// 原文:` とメモで確かめる。`python3 -m mext changed X.mext` で、書き起こしの後に人が直していないかを見る（直していれば、それも読みの一部として扱い、レポートに書く）。解いていなければ `mext solve` する（`[ai]` は変えない）。
2. **ひな形**: `python3 -m mext compare --init A.mext B.mext -o A.vs.B.compare`。文言が同じ結論と前提は自動で対応づけられる。文言の近い組は注として出る（機械的な候補にすぎない）。
3. **結論を対応づける**: 対応のない最終的な結論ごとに、`// 出典:` が指す原文の箇所を両方の読みで見比べ、**同じ命題を指すものだけ** `match "A の文言" "B の文言" ; 理由` と書く（`comparing.md` §1）。言葉が似ていても主張の強さや対象が違えば、そう理由に書く。対応がないものは無理に対応づけない。
4. **一度比べる**: `python3 -m mext compare A.vs.B.compare -o A.vs.B.compare-result.md`。
5. **前提を対応づける**: §2 の表の決め手（単独で外すと成り立たなくなる前提）を見て、二つの読みが**同じ判断**を書いたものを `match` で対応づけ、もう一度比べる。これで「共通の決め手」が出る。
6. **原文に戻る**: 違い（成否、決め手、補った前提、独立した経路、結び方）ごとに原文を読み、`comparing.md` §2 の四つ（書き起こしの誤り・粒度の違い・判断の違い・原文の曖昧さ）のどれかに分ける。どちらの読みが原文に忠実かを言えるなら、根拠を添えて言う。言えなければ、そう書く。
7. **レポート**: `comparing.md` §3 の章立てで `A.vs.B.compare.md` を書く。会話には §0 とファイルの一覧を返す。

三つ以上の読みを比べるときは、一つを基準にして、ほかの読みとの組ごとに比べる。

## 守ること

- 対応づけは、二つの読みを一致させるためではなく、同じ命題を見つけるためにする。違うものを同じとみなして違いを消さない。
- どちらかの読みを書き直さない。書き起こしの誤りを見つけたら、レポートで指摘し、直すのはその読みの作り手（または利用者）に任せる。
- 数字は `mext compare` の出力に従う。両方の読みで成り立つことを「論証が正しい」ことの根拠にしない（両方とも同じ点を書き落としているかもしれない）。
- あなたが一方の読みを作った AI と同じ（またはそれ自身）なら、その旨をレポートに書く。
