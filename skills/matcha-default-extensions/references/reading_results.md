# mext の出力の読み方

数字と導出（Extension の数・内容、preferred か否か、懐疑的・信憑的帰結、依存）は、**必ず mext の出力に従う**。自分の推論で上書きしない。食い違いに気づいたら、その事実をレポートに書く。

## 結果を強く読みすぎない

- **Extension が一つで、主な結論が懐疑的帰結に入っても、「論証が正しいと確認された」ことにはならない**。doubtful の評価も推論を止めないし、反対の根拠は書き起こされていなければ理論にない。
- **Extension の数、懐疑的帰結の数、Lean の検査、audit の ✓ を、結論の根拠として前に出さない**。どれも、書き起こした理論の中で計算が正しいこと、手順が記録されていることを示すだけで、原文の論証が正しいことは示さない。レポートの冒頭は、実質的な所見（何に依存し、どこが弱いか）から書く。
- **Lean の検査が示す範囲**: `mext lean` の出力が Lean で通れば、列挙された各集合が Extension であること、優先順位があれば preferred とされた Extension が preferred であることが確かめられたことになる（`--import-spec` で `lean/MextSpec.lean` を使えば、Reiter の定義と preferred の定義まで、健全性定理で示す）。preferred でないとされた Extension が本当にそうでないこと、Extension が漏れなく列挙されたこと、そして書き起こしや審査の妥当性は示さない。レポートにはこの範囲を書く。
- summary の「検証の範囲」を必ず添える。とくに、**対立する命題のない結論**は、反対の根拠に勝ったのではなく、反対の根拠が書かれていないだけである。言葉を変えずに伝える。
- 依存が「—」の結論は、「調べた範囲（表の『調べた範囲』の列と summary の冒頭）では見つからなかった」と書く。「依存しない」とは書かない。

## 何に依存しているか（感度分析）

「何に依存しているか」は、自分の読みではなく `sensitivity` と `summary` の出力から書く。

| 出力 | 意味 | 書き方 |
|---|---|---|
| 単独で外すと成り立たなくなる | それ一つで結論を崩す前提 | 決め手として書く |
| 組の一員 | これ一つを外しても残るが、これを含む組を外すと崩れる | **それだけで崩れる弱点のように書かない** |
| 独立した N つの経路 | 各経路から一つずつ外して初めて崩れる | 経路の数を強さとして書く前に、`concern` / `distinct` の判断を示す（なければ判断して `[ai]` に書き、解き直す） |
| 複数の経路に共通する判断 | あてはめを一か所ずつ外しても残るが、判断ごと採らなければ崩れる | 経路が複数あっても、この判断が一つの弱点であると書く |
| 原文にない前提（補ったもの）に依存する | 決め手が書き起こした者の補った前提 | その前提を補わない読みでも成り立つかを原文に照らして確かめ、結論の節に書く。決め手が書き起こしの側にあるなら、原文の論証の強さではなく書き起こしの選択の結果である |
| 外すと否定が成り立つ | 反論の立証で結論が逆転する前提 | 反論の候補（立証責任）として書く |
| 〔一部の Extension には残る〕の付いた決め手 | 外すと、すべての読みでは成り立たなくなるが、一部の読みには残る（浮動する結論の片方の経路など） | 「どの読みからも導けなくなる」とは書かない |
| 一部の Extension でだけ成り立つ結論の決め手 | その結論が成り立つ読み（Extension）の中での依存。外すと、どの preferred Extension にも入らなくなる | 「その読みを採るなら、これが決め手」と書く。読みの間の対立（優先が決まらないこと）とは別の弱点である |
| 退けた反論（`!#`）にかかわる結論の決め手が「—」 | 退けた反論は、退けた理由（評価）を外しても、立証されないまま成り立たない。だから、その理由は決め手に現れない（立証責任の読み） | 退けた理由の重みを見たいなら、反論を立証された主張とし、退ける側を例外（`!>`）にした試算を作る。「決め手がない」と書かない |
| 外すと新たに成り立つ結論 | 非単調性。その前提が別の結論を打ち消していた | 必要なら書く |

## 結び方（connectives）

結論を左右する結び方のうち、原文に明示がない（読み）か未記録のものは、結論から逆算した結び方でないかを原文に照らして確かめ、結果を（AND / OR を変えない場合も）レポートに書く。

## 原文に戻る場所

原文をすべて読み直す必要はない。道具が指した箇所に戻る: 結論を左右する結び方、summary の争点、事実の種別や補った前提が効いている箇所。summary の争点には、`.matcha` の行、原文の出典（`// 出典:`）、`[ai]` の行、試算のファイル、導出をたどる `mext explain` のコマンドが添えてある。
