# レポートの章立て

利用者の言語で書く。プログラムの出力は「（mext の出力）」と明記して、手を加えずに貼る。あなたの解釈とはっきり区別する。長い出力（report・sensitivity・connectives・explain の全体）は、別のファイルに置いて名前で参照させてよい。

## mext分析のレポート（`X.mext-analysis.md`）

```
# mext分析: X

（長さ: 要点／標準／詳細。聞けなかった場合はその旨）

## 0. 結論        … 3〜6 行。**実質的な所見から書き始める**: (b) 実質的に説得的か、(c) 何に依存しているか
                    （決め手の評価・補った前提・優先順位。sensitivity / summary から）、(a) 形式的に導けるか。
                    検証の範囲を一行で添える。Extension の数・懐疑的帰結の数・Lean の検査を冒頭に置かない
                    （それらは書き起こした理論の中での導出可能性にすぎず、前に出すと結果を強く読ませる）
## 0.1 読む順番   … 争点の上位 3 つ（summary の争点の行）と、それぞれをたどるファイル（.matcha の行、試算、explain）。
                    出力のファイルが多いので、読み手がまず何を見ればよいかを示す
## 1. 文書の論証   … 要約と、書き起こした範囲
## 2. 書き起こし   … X.matcha の要所、対応表の要約、補った前提、落としたもの、lint、改訂の記録、
                    結び方の感度と原文で確かめた結果、事実の種別。人の改訂を見つけた場合は、その扱い
## 3. 構文チェック  … （matcha_check の出力）
## 4. AI の判断    … [ai] / [extra] の表と理由。保留した判断
## 5. Extension    … 一覧、preferred、主な結論の導出（explain）。Lean の検査の結果はここか付録に書く
## 6. あてはめの妥当性と感度 … review の表、補った前提の審査、summary の表（結論ごとの依存）、試算
## 7. 懐疑的帰結と信憑的帰結
## 8. 反論の候補（立証責任） … どの評価を争えば、どの事実を示せば、結論が変わるか
## 9. 予測の検証   … [claimed]（事前の予測）と verify の結果。食い違いは、書き起こしの誤り・原文の飛躍・直観の誤りのどれか
## 10. 総評        … 強いところと弱いところ、形式化して初めて見えたこと。書き起こしと審査を同じ AI がした限界
## 付録: ファイル一覧、mext audit の結果
```

| 長さ | 内容 |
|---|---|
| 要点 | 本文 2,000 字程度。§0 と §10 を中心に、弱点の上位 3 つを支える部分だけ |
| 標準 | 本文 6,000 字程度（貼った出力は数えない）。全章、表は要約して |
| 詳細 | 制限なし。表と導出を省かずに |

## matcha-default-extensions のレポート（`X.report.md`）

```
# Extension レポート: X.matcha

## 1. 構文チェック  ## 2. AI の判断  ## 3. デフォルト理論（report の表。原子が 40 を超えたら要約）
## 4. Extension（一覧と主な結論の導出）
## 5. 著者の成否（+ / !）との照合 … 不一致の原因（原典の誤記か、変換の読みか、AI の判断か）。印がなければ「印なし」
## 6. あてはめの妥当性 … review の表、構造の問題、誤記の疑い、asis との違い、誤記訂正の試算
## 7. 懐疑的帰結と信憑的帰結  ## 8. 反論の候補（sensitivity の表）  ## 9. 予測の検証
## 10. 結論 … 検証の範囲を添え、(a) 形式的妥当性と (b) 実質的妥当性を分けて述べる
```
